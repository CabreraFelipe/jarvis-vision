# Cierre completo de la sesión (candidato V0.5.3)

Incidencia física comunicada: abrir/cerrar JARVIS deja procesos Python en segundo plano. No se conocen PID, línea de comando ni causa exacta. El código V0.5.2 destruye Tk sin esperar trabajadores de captura, voz, IA y diagnóstico. Se añade cierre idempotente, cancelación de nuevas tareas y escucha, espera global de hasta dos segundos; en el ejecutable un watchdog de cinco segundos intenta finalizar únicamente el proceso actual si el cierre se atasca. El punto de entrada termina explícitamente después del cierre para evitar bloqueos de finalización de bibliotecas nativas; guarda preferencias y memoria mediante escrituras síncronas existentes. Se conserva salida 42 de actualizaciones. El gestor revisión 2 usa un Job Object Windows privado KILL_ON_JOB_CLOSE para el proceso que crea y sus descendientes asignados; no enumera ni mata por nombre, no toca Ollama ni otros Python. Si Windows restringe crear/asignar el job, mantiene espera del hijo directo y cierre cooperativo, sin prometer contención de descendientes. La asignación ocurre inmediatamente después de Popen; no es contención previa a ejecución. Un driver que monopoliza el GIL podría impedir el watchdog Python. Estas limitaciones requieren validación física. Se añade prueba de aislamiento con un proceso no relacionado y cierre cooperativo y acotado. No se modifica la versión estable hasta CI. Revisar procesos con línea de comando, no terminar todos los python.exe. Para revisión 2 usar mecanismo autenticado de revisión 1 ya instalado; si no migró, migración autenticada explícita. Probar apertura/cierre repetido, durante captura, escucha, respuesta, lectura y actualizaciones; comprobar en Administrador de tareas los procesos de la instalación, no los servicios externos.
